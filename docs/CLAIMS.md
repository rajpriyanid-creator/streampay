# StreamPay v2.5 — Claims & Verification Matrix

This document tracks all protocol and technical claims against empirical test evidence.
Every status must be backed by a linked reproducible output. TypeScript compilation alone is NOT sufficient evidence.

| Claim ID | Protocol Claim | Status | Verification Evidence |
| :---: | :--- | :---: | :--- |
| **CLM-01** | Bounded escrow session opening on Monad Testnet | **NOT DEPLOYED** | Foundry unit tests pass on Anvil. Testnet deployment not yet executed. |
| **CLM-02** | Zero-gas off-chain micro-vouchers via EIP-712 | **PARTIAL** | `lifecycle.ts` uses raw digest signing. Cross-library parity vectors not independently run. |
| **CLM-03** | Monotonic cumulative units & replay protection | **PASS (unit test)** | Contract `_applyVoucher` rejects `newUnits <= settledUnits` — verified by Foundry test. |
| **CLM-04** | Merkle manifest segment content integrity | **PASS (code)** | SHA-256 of real generated bytes used in manifest. Verify end-to-end with `generate_manifest.js` output. |
| **CLM-05** | Push-with-pull fallback payout accounting | **PASS (code & test)** | `MockBadToken` tests implemented in `StreamPaySettlement.t.sol` (`test_pushWithPullFallback_mockBadToken_cooperativeClose`), verifying failure fallback to `claimable` and subsequent `claim()`. |
| **CLM-06** | Elapsed-plus-lead bound enforcement | **PASS (unit test)** | Contract reverts `ExceedsElapsedPlusLead` — verified by Foundry fuzz test. |
| **CLM-07** | Single-use HMAC segment access tokens | **PASS (code)** | Token consumption validates stream/segment binding before consuming. Wrong-path tokens preserved. |
| **CLM-08** | Automated sweeper worker for checkpointing & defense | **PARTIAL** | Sweeper has continuous loop, chain verification, and idempotent tx handling. Not tested with live sessions. |

| **CLM-11** | No production private keys in client bundle | **PASS** | Hard-coded Anvil keys restricted to LOCAL mode only. Testnet requires real wallet. |
| **CLM-12** | Valid offer configuration passes contract constraints | **PASS** | `unitPrice * maxCreditWindowUnits <= maxUnredeemedAmount <= deposit` enforced with client-side validation. |

| **CLM-15** | Stream allowlist enforcement | **PASS (code)** | Server rejects unknown stream IDs. No auto-creation of arbitrary manifests. |
